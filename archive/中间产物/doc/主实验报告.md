# 主实验报告

本报告记录当前已完成的正式主实验。规模验证和 seed 鲁棒性验证尚未进行，因此本文结论仅适用于当前主实验配置，不能视为最终课程实验结论。

## 1. 实验目标

本阶段研究 skewed CSR SpMV 中 dynamic、guided 和 long-row 三种策略在不同 skew level 和线程数下的性能 trade-off。

static 和 nnz-aware 已在助教 baseline 中出现，作为已有参考，不是本阶段的主要探索对象。本阶段重点比较 dynamic、guided 和 long-row。

## 2. 实验环境

- 处理器：Intel Core Ultra 9 285H
- 运行环境：WSL Ubuntu
- WSL 可见资源：16 CPUs，16 cores，1 thread/core
- 共享缓存：24 MiB L3
- 编译器：GCC 15.2.0
- OpenMP runtime：GCC libgomp
- 编译参数：`-O2 -std=c++17 -fopenmp -pthread`

所有正式实验统一使用以下 OpenMP runtime 环境：

```text
OMP_WAIT_POLICY=PASSIVE
OMP_DYNAMIC=FALSE
OMP_PROC_BIND=false
OMP_PLACES unset
```

这些设置在所有正式实验中保持一致，用于控制 OpenMP runtime 环境，不属于任何单一策略的额外优化。

## 3. 矩阵与实验变量

主实验固定参数：

- `rows = 20000`
- `cols = 100000`
- `long_rows = 200`
- `seed = 20260926`

三个 skew level 如下：

| Level | normal_nnz | long_nnz | Skew |
| ---: | ---: | ---: | ---: |
| 1 | 90 | 690 | ≈ 6.19 |
| 2 | 75 | 2175 | ≈ 21.66 |
| 3 | 50 | 4650 | ≈ 47.44 |

线程数为 `1, 2, 4, 8, 16`。Dynamic 和 guided 测试的 chunk 为 `1, 2, 4, 8, 16, 32, 64`。

三个 Level 的 long-row fraction 均为 1%，平均 NNZ/row 均约为 96。因此三个 Level 主要改变行长度偏斜程度，而不是平均工作量。

## 4. 三种策略实现

### Dynamic

Dynamic 使用标准 CSR 行级 OpenMP 并行，每个迭代处理一整行。探索阶段在 `spmv_omp_student_1` 中使用 `schedule(runtime)`，通过 `OMP_SCHEDULE=dynamic,chunk` 测试7个 chunk，等价于探索不同的 `schedule(dynamic, chunk)` 配置。

### Guided

Guided 同样使用行级 OpenMP 并行，通过 `schedule(runtime)` 和 `OMP_SCHEDULE=guided,chunk` 测试7个 chunk，等价于探索不同的 `schedule(guided, chunk)` 配置。

### Long-row

Long-row 使用 `row_nnz > average_nnz` 识别 synthetic long rows。普通行由单个线程按整行计算；长行在同一个 OpenMP team 内按 NNZ 区间拆分。每个线程批量计算所有长行中属于自己的 partial sums，统一同步后，再通过 OpenMP `for` 并行归并不同长行。

该实现不使用 nested parallelism 或额外线程。一次 SpMV 只保留 O(1) 次团队级同步，不再逐条 long row 同步。

## 5. 测量方法

正式主实验包含225个逻辑配置：dynamic 105个、guided 105个、long-row 15个。每个逻辑配置启动5个独立进程，共得到1125条 raw records。

每个进程的测量过程为：

- 先执行1次 warm-up，并完成正确性检查；
- 使用 `repeats=10` 执行10次正式调用；
- process-level runtime 为10次调用总时间除以10；
- 每个逻辑配置以5个 process-level runtime 的 median 作为主结果；
- mean、min 和 max 仅作为运行波动参考。

实验按5轮完整扫描执行，每轮对225个逻辑配置各运行1次，而不是连续执行同一配置5次。所有1125条正式记录的 correctness 均为 `pass`。

## 6. Chunk 参数结果

在15个 `Level × threads` 场景中，有13个场景满足：dynamic 或 guided 至少一种策略的最佳 chunk 与第二佳 chunk 的 median 差距小于3%。

最佳 chunk 会随 Level、线程数和策略变化，正式数据中不存在明显的全局唯一最优值。因此，chunk 应理解为场景相关的调度参数，而不是固定最优常数。

## 7. Strategy × Threads × Skew 结果

下表列出4、8和16线程下 dynamic 与 guided 的最佳 chunk median，单位为 ms。

| Level | Dynamic 4T | Guided 4T | Dynamic 8T | Guided 8T | Dynamic 16T | Guided 16T |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 0.658 | 0.591 | 0.516 | 0.425 | 0.457 | 0.459 |
| 2 | 0.663 | 0.595 | 0.490 | 0.482 | 0.472 | 0.511 |
| 3 | 0.646 | 0.597 | 0.501 | 0.498 | 0.417 | 0.464 |

4线程时，guided 在三个 Level 下均快于 dynamic，观察到较稳定的优势。

8线程时，Level 1 的 guided 明显快于 dynamic；Level 2 两者差距约为1.66%；Level 3 差距约为0.60%。在当前数据中，随着 skew 提高，8线程下 dynamic 与 guided 的结果逐渐接近。

16线程时，Level 1 的 dynamic 为0.457 ms、guided 为0.459 ms，二者基本持平；Level 2 的 dynamic 为0.472 ms、guided 为0.511 ms；Level 3 的 dynamic 为0.417 ms、guided 为0.464 ms。观察到随着 skew 提高，dynamic 相对 guided 的优势增强，但这一表述仅描述当前主实验趋势，不代表已经验证的因果关系。

## 8. Long-row 结果

Long-row 没有在15个 `Level × threads` 场景中的任何一个取得第一。Level 3 的结果如下，单位为 ms。

| Threads | Dynamic best | Guided best | Long-row |
| ---: | ---: | ---: | ---: |
| 1 | 2.293 | 2.264 | 2.472 |
| 2 | 1.287 | 1.297 | 1.495 |
| 4 | 0.646 | 0.597 | 0.820 |
| 8 | 0.501 | 0.498 | 0.747 |
| 16 | 0.417 | 0.464 | 0.937 |

Long-row 解决了纯行级策略无法拆分单条长行的问题。但在当前 synthetic workload 下，行内拆分、partial sums 存储和归并的额外开销没有被负载均衡收益抵消，因此当前实现表现为负优化案例。这一结果不能泛化为 long-row 方法在其他矩阵上没有价值。

## 9. Scalability

下表给出16线程相对同一 Level、同一策略1线程最佳 median 的 speedup。

| Level | Dynamic | Guided | Long-row |
| ---: | ---: | ---: | ---: |
| 1 | 5.02× | 5.21× | 3.70× |
| 2 | 4.88× | 4.39× | 3.07× |
| 3 | 5.50× | 4.88× | 2.64× |

当前数据中，long-row 的16线程扩展性弱于 dynamic 和 guided；随着 skew 从 Level 1 提高到 Level 3，long-row 的16线程 speedup 从约3.70×下降到约2.64×。

## 10. 当前主实验结论

1. Dynamic 和 guided 没有绝对的全局最优，表现随线程数和 skew 变化。
2. Guided 在4线程下的三个 Level 中均表现较好。
3. 在较高线程数和较高 skew 的部分场景中，dynamic 相对 guided 的竞争力增强，并在部分配置下反超 guided。
4. Chunk 会影响性能，但绝大多数场景中最佳与次佳 chunk 差距较小，不存在统一的最优 chunk。
5. 当前 long-row 实现完成了行内拆分，但额外管理与归并成本较大，在本实验场景中没有超过 dynamic 或 guided。
6. 当前结论仍需后续 size validation 和 seed robustness 验证，不能声称已经具有跨规模或跨 seed 的普适性。
